The /lifeline toolkit.

Seven slash commands that compose into an end-to-end harness: spec → loop → deliver → review → PR → approve. The /deliver command analyzed in this post is the newest of them, ported from OpenAI Codex's /goal templates.

Command
What it does
/lifeline:planner
Phase · Design
Pairs with /superpowers:writing-plans
Design-spec writer. Walks through clarifying questions → approaches → section-by-section design → codex exec review on the result, applies your chosen findings. Output lands in docs/superpowers/specs/.
/lifeline:loop
Phase · Build
Spec → harness → PR
Autonomous dev harness. Gathers requirements, generates app_spec.md, then runs the Coder + Reviewer inner loop per feature with cloud-Codex review after push. Project-agnostic — reads CLAUDE.md for stack-specific commands.
/lifeline:deliver ★
★ Featured · Goal loop
Pure mode + Paired mode
Goal-driven in-session loop. Takes an objective, iterates Claude actions until a completion audit passes. /deliver pair swaps the audit for an independent codex exec grader running read-only — the Outcomes pattern in 50 lines of Markdown.
/lifeline:review
Phase · Verify
Single pass · local
Local Codex code review. Runs npm run review against the staged diff, parses findings from .codex-reviews/latest.md, and applies fixes. One pass per invocation — no polling.
/lifeline:request-pr
Phase · Ship
Pairs with /lifeline:approve-pr
PR opener. Auto-generates title + body from the commit list, refuses detached HEAD, dirty trees, or behind-upstream branches. Resolves base via git config / gh repo defaults.
/lifeline:upsource-review
Phase · Iterate
Self-driving · cloud reviewers
PR review fix-loop. Fetches findings from Claude Code Review + chatgpt-codex-connector, fixes them in atomic per-cycle batches, runs codex verify on the staged diff, replies + resolves threads, polls for the next review cycle.
/lifeline:approve-pr
Phase · Finish
End-to-end merge
PR finisher. Squash + delete remote branch, sync local main, delete the local feature branch, clean up associated git worktrees (safely — dirty/locked worktrees are preserved).
One harness, seven commands. Spec writes itself, the loop builds, deliver finishes, review verifies, request-pr ships, upsource-review iterates, approve-pr closes the loop.
