lifeline harness · hook wiring

Two hooks, two paths, one decision.

The lifeline harness wraps Claude Code with two PreToolUse hooks that fire on every Bash and feature-list edit. Both the CLI subprocess path and the SDK in-process path converge on the same Python predicates, so the rules stay in one place.

properties
Fail-closed import
hook_runner.py wraps imports in try / except. If security or hooks fails to load (bad syntax, missing dep), the runner emits an explicit block and exits 0 — so Claude sees a deny, not a silent allow.
shlex.quote on paths
Claude CLI runs hooks via sh -c. Unquoted paths split at spaces (Windows C:\Program Files, macOS /Users/John Doe/...) and the runner is never invoked. shlex.quote kills the footgun.
No-decision = ALLOW
Claude's CLI defaults to allow when a hook returns no JSON. The fail-closed import + explicit return of {} for "not our concern" is what keeps the allowlist load-bearing.
The harness rules live in one place (Python). The two backends are interchangeable wiring, not duplicated logic.
